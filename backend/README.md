# BaseGrid Safety API

Node.js API for BaseScan25, deployed on Render with PostgreSQL. No Cloudflare account, Workers, D1, or Wrangler is required.

## Product behavior

- Free instant lookup; $1.49 USDC per paid research brief on Base Mainnet.
- The researched asset may be on another supported network; payment is always native USDC on Base.
- Payment monitoring checks the USDC contract, receiving wallet, exact amount, payer, order creation block and expiry, then waits for 12 confirmations.
- Security adapters: GoPlus for mapped EVM networks, RugCheck for Solana, and DEX Screener for market discovery. Unsupported chains return explicit unknown coverage.
- Reports are stored in PostgreSQL and can be retrieved with the unguessable order UUID. Resend email and OpenAI-generated explanations are optional.
- AI explanations are evidence-bound summaries, not security verdicts or audits. API usage may incur charges.

## Deploy on Render

1. Open [Render Blueprints](https://dashboard.render.com/blueprints) and create a Blueprint from this repository. The root `render.yaml` provisions only the Node web service, avoiding the extra database resource that can trigger Render's 25-resource workspace limit.
2. In the Render service's environment settings, set `DATABASE_URL` to the **internal connection URL of an existing PostgreSQL database** accessible from this service. The app needs a database; this Blueprint intentionally does not create one. Do not paste database URLs or credentials into chat or commit them to GitHub.
3. Set `PAYMENT_RECIPIENT` to the receiving wallet you intend to use and verify the address before launch. `ADMIN_SECRET` is generated by the Blueprint. Keep all secrets in Render.
4. Optional email delivery: set `RESEND_API_KEY` and `FROM_EMAIL` to a verified sender. Optional AI summaries: set `OPENAI_API_KEY`.
5. Wait for deployment and open `https://YOUR-RENDER-SERVICE.onrender.com/api/health`. Confirm the response says the service is healthy and `paymentVerifierConfigured` is true. A healthy process alone does not prove a real payment has been verified.
6. In GitHub, open **Settings → Secrets and variables → Actions → Variables** and create repository variable `BASEGRID_API_URL` with the exact deployed Render service origin (for example, `https://YOUR-RENDER-SERVICE.onrender.com`, no trailing slash).
7. Run **Actions → Publish BaseGrid 25 to GitHub Pages → Run workflow**. The workflow injects that URL into both page meta tags during the build. Verify the deployed site and Token Safety Lab can call `/api/scan`.
8. Before announcing paid checkout, test a small real $1.49 USDC order on Base Mainnet with the configured receiving address, report generation, and (if configured) email delivery. Never make a second payment just because the UI is waiting.

The payment verifier runs every 60 seconds in the Node service. For production, configure a reliable Base RPC endpoint; the public RPC may rate-limit log scans. Render services and PostgreSQL are billable and pricing/availability can change.

## Local development

Requires Node.js 22+ and a PostgreSQL database.

```sh
npm install
DATABASE_URL='postgres://…' PAYMENT_RECIPIENT='0x…' ADMIN_SECRET='use-a-long-random-secret' npm start
```

The server initializes the PostgreSQL schema on startup. Set `DATABASE_SSL=disable` only for a local database that does not support TLS.

## API

- `GET /api/health` — service/configuration status.
- `GET /api/scan?network=base&asset=0x...` — provider aggregation.
- `POST /api/order` — create a $1.49 order.
- `GET /api/order/{uuid}` — order status.
- `GET /api/order/{uuid}/report` — report JSON (UUID is a bearer secret).
- `POST /api/admin/verify` — protected manual payment-monitor run; requires `Authorization: Bearer $ADMIN_SECRET`.

## Launch checklist

- Set the correct payment recipient and API URL.
- Confirm the verified email sender if email delivery is enabled.
- Add rate limits, anti-spam controls, data retention/deletion, a support contact, terms, and refund policy.
- Test payment confirmation, duplicate transaction handling, report generation, email delivery, and error paths.
- Do not market this as a complete auditor of every chain. Sui, TON, Bitcoin, and other unconfigured ecosystems still need dedicated adapters and independent test coverage.
